# PermutiveAPI 6.9.0

PermutiveAPI 6.9.0 makes the Codex plugin the streamlined front door for setup, readiness checks, troubleshooting, and governed execution while preserving the canonical typed SDK underneath.

## Added

- Dedicated Codex `welcome` and `troubleshooting` skills for first-use onboarding and recovery.
- `permutiveapi check` as the single readiness command for secret-safe credential resolution and one bounded read-only Permutive API connectivity check.
- Structured readiness JSON with stable error codes, retryability, recommended actions, and sanitized context.
- Deterministic regression tests for successful readiness, missing credentials, authentication failures, bounded read behavior, secret redaction, and plugin packaging.

## Changed

- Codex setup now follows `check -> targeted repair -> check -> execute` instead of exposing Python plumbing or a long diagnostic checklist.
- Stable PyPI installation is used for normal plugin bootstrap; Git installation remains a development-only path.
- `permutiveapi doctor` remains available as the focused local `.env` hygiene diagnostic rather than a mandatory step for every workflow.
- Codex plugin metadata and package release metadata are synchronized at 6.9.0.

## Security

- API keys remain local and are never requested in chat, echoed, logged, uploaded, or stored in plugin configuration.
- Readiness probes are read-only and bounded.
- Mutating workflows remain read-only by default and still require explicit confirmation before execution.
- Failure reporting uses secret-safe actionable guidance rather than raw sensitive exception messages.

## Compatibility

6.9.0 is a backward-compatible minor release. No supported 6.x SDK, transport, resource, query, plugin, MCP, or governance API is removed. Existing CLI and programmatic integration workflows remain supported.

## Release integrity

The 6.9.0 candidate must pass protected Python CI, AI-native validation, release metadata, generated API contracts, replay validation, performance budgets, package build and clean-install smoke tests. The release workflow then publishes the exact immutable candidate through PyPI Trusted Publishing, verifies the public PyPI installation, and creates the matching annotated tag and GitHub Release with distribution, SBOM, manifest, and attestations.
