# PermutiveAPI 6.8.0

PermutiveAPI 6.8 is a consolidation release. It keeps the 6.x API compatible while making the SDK easier to reason about, type-check, validate, and release.

## Highlights

- A typed canonical resource registry records the five supported CRUD resource families and their 25 canonical operations.
- Generated package-root public-surface evidence classifies canonical, integration, and compatibility exports without changing existing imports.
- Agent, plugin, MCP, and tool surfaces share a compact typed integration registry.
- Consolidation evidence combines public API, resource, capability, and integration contracts into deterministic JSON with a stable SHA-256 fingerprint.
- New consolidation modules are part of the strict Pyright contract and package validation surface.
- Regression tests prevent resource-contract drift, duplicate resource operations, public-export classification gaps, and nondeterministic evidence.

## Compatibility

No supported 6.x package-root import is removed. Legacy resource exports remain compatibility APIs. The release adds internal contract/evidence modules without introducing a second client, transport, resource, plugin, or governance model.

## Security and reliability

The existing secret-safe diagnostics, URL credential redaction, bounded retries, shared rate-limit coordination, atomic credential rotation, recording/replay, and immutable release-evidence contracts remain in force. The 6.8 consolidation tests make those cross-cutting contracts easier to validate without duplicating policy.

## Release validation

The release candidate must pass formatting, NumPy docstrings, strict Pyright, Python 3.9–3.13 tests, coverage, package build and Twine checks, clean wheel installation, AI-native validation, CodeQL/security checks, immutable release-manifest verification, PyPI Trusted Publishing, and public-PyPI smoke verification.
